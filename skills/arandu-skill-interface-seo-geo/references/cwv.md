# Core Web Vitals in Kyse views

## LCP (largest contentful paint)

- Identify the LCP element of each template (usually the hero image or headline).
- The hero image is `components.ResponsiveImage` with `Eager: true` (eager loading + high fetch priority), real `Width`/`Height`, `SrcSet` + `Sizes`, AVIF/WebP via `Sources`. Every other image stays lazy (the default).
- No hero image behind a script, a carousel, or a fade-in that starts at opacity 0.
- Fonts: `{!! fonts.Preloads() !!}` in the head; `font-display: swap` with the metric fallback faces `aru font:add` generates.

<!-- example: examples/kyse/media.go#HeroImage -->
```go
// HeroImage is the largest element of the first screen: loaded eagerly with
// high priority, with its intrinsic size written so nothing shifts.
func HeroImage() template.HTML {
	return components.ResponsiveImage(components.ResponsiveImageProps{
		URL:    "/images/painel-cobrancas-1600.webp",
		Alt:    "Lista de cobranças de outubro com status Emitida, Paga e Vencida",
		Width:  1600,
		Height: 1000,
		SrcSet: "/images/painel-cobrancas-800.webp 800w, /images/painel-cobrancas-1600.webp 1600w",
		Sizes:  "(min-width: 1024px) 60vw, 100vw",
		Eager:  true,
	})
}
```

## CLS (layout shift)

- Every image and video has intrinsic size; embeds reserve their box.
- Content that arrives later (HTMX swaps, `LazyLoad`) has a placeholder of the same size (`Skeleton` shaped like the result).
- Banners (cookies, announcements) overlay or reserve space; never push content after load.
- Fallback font metrics match the vendored face (generated by `aru font:add`).

## INP (interaction)

- Behaviours do little work on input; long work moves off the handler; no layout reads in loops.
- HTMX requests show their indicator within 100 ms.

## Assets

Everything is embedded and content-addressed (`view.Asset`), so caching is long and safe; keep `custom.js` small, and vendor heavy libraries only for the page that needs them.
