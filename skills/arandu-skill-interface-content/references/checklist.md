# Content harmony checklist

## Vocabulary
- [ ] Each entity, action and status has a single name across the product.
- [ ] No forbidden glossary term appears in views, translations or e-mails (search run, command recorded).
- [ ] Panel names match the landing, e-mails and help.
- [ ] The vocabulary is the niche's own in Portuguese, not a literal translation of English.

## Structure
- [ ] The landing follows the order recorded in the profile.
- [ ] Every promise on the landing corresponds to a screen or feature that exists.
- [ ] Plans differ by criteria the niche recognises.

## Specificity
- [ ] No phrase from `generic-phrases.md` remains.
- [ ] Each section title states a result or a concrete action.
- [ ] No number, customer, testimonial or integration was invented.

## Tone
- [ ] The voice is present on every screen, alert and e-mail.
- [ ] Tone changes with the journey moment; the voice does not.
- [ ] One form of address throughout ("você").
- [ ] The same formality in panel, e-mails and landing.

## Microcopy
- [ ] Every button says exactly what happens (verb + object).
- [ ] An action keeps its verb from button to confirmation to status.
- [ ] Every empty state says what to do next, with its own button.
- [ ] Every error says what happened and how to recover, without apologising.

## Real content
- [ ] No Lorem Ipsum, "Texto aqui" or generic sample data on any screen.
- [ ] No template or cloud-provider default text left.
- [ ] Screens tested with the shortest and longest plausible text.
- [ ] Each screen answers what the user came to do and what comes next.

## Originality
- [ ] No sentence copied or lightly adapted from a reference.
- [ ] No competitor named without an explicit request.
- [ ] The difference recorded in the profile appears in the main promise.
